01 / Start with the owner request

The selected top-level model coordinates

You provide the request. The coordinator creates the private plan.

Open the Factory checkout in a top-level Codex task. Paste this prompt, fill in the target and request fields, and continue in that task:

Read and follow skills/codex-factory/SKILL.md completely.
Target repository: <absolute path to the existing repository or new destination>
Owner request: <paste the prompt, specification, or plan here>

The coordinator inspects an existing clean repository or bootstraps one explicit new destination, creates campaign.json privately, previews bounded routes, runs only authorized workers, integrates accepted commits, and returns evidence for your review. You never author Factory JSON.

02 / The operating loop

A small control plane around existing runtimes

Prompt. Inspect. Plan. Preview. Dispatch. Accept.

  1. 01

    Give the owner prompt

    Supply a normal-language request and an existing repository or one explicit new destination. The selected top-level Codex model is the coordinator.

  2. 02

    Inspect or bootstrap

    Preserve owner work. Intake requires a clean repository or refuses to overwrite any existing bootstrap destination.

  3. 03

    Create the private plan

    The coordinator decides whether decomposition helps and writes task scopes, checks, dependencies, and safe parallelism under ignored Factory state.

  4. 04

    Preview bounded routes

    Qualified local capacity comes first. A short local failure may fall back to Luna, then Terra, only when qualified and admitted.

  5. 05

    Dispatch bounded workers

    Independent non-overlapping tasks may share configured slots. Every worker is a scoped leaf with one attempt and retained receipts.

  6. 06

    Accept the integration evidence

    The coordinator integrates only accepted results, reruns acceptance checks, and keeps the integration branch separate from the owner branch.

03 / Controls

Bounded by design

The worker does the shift. The coordinator keeps authority.

The coordinator concentrates on admission, execution, integration evidence, and bounded dependency-safe delegation.

QUALIFICATION

Role failures stay local

A failed structured-write check does not remove a model that still qualifies for read-only analysis.

ADMISSION

Paid use is explicit

Codex candidates require an opt-in qualification flag and a remaining aggregate reservation.

PROCESS

Timeouts own the process tree

The supervisor handles timeout and interrupt cleanup; an unreaped process preserves the lock as a stop condition.

EVIDENCE

Completion is not acceptance

A clean CLI exit is recorded as process completion. It does not claim the requested work is correct.

05 / Receipts

Evidence survives the shift

Enough context to accept, reject, or investigate.

Each run retains the exact request, JSONL events, stderr diagnostics, final message, terminal result, and aggregate usage record. Raw receipts remain local and ignored by Git because they can contain repository data.

06 / First shift

Node.js 24+ · Git · Codex CLI

Inventory first. Spend nothing.

The qualification command previews every applicable candidate and harness pair by default. Add --execute to test free local candidates. Paid Codex models remain excluded unless you add --include-paid.

07 / Honest boundary

Evidence-producing prototype

A useful supervisor. Not yet the whole factory.

The coordinator supports qualification-gated local-first campaigns with bounded fallbacks. It remains suitable for controlled operation on a host you operate—not unattended product delivery.

WORKING NOW
  • Dynamic Ollama inventory plus configured Luna, Terra, and Sol candidates
  • Exact, role-scoped qualification fingerprints
  • Free-local-first selection from the qualified pool
  • Constrained local structured-file patch path
  • Owned process tree per worker, with three configured slots, timeout, and receipts
NOT INCLUDED
  • PM-facing control room or remote web application
  • Automatic semantic acceptance, merge, or release
  • MCP server or autonomous repository-wide local agents
  • Hard token cutoff during a Codex turn
Two kinds of budget

Local Ollama workers use wall time, concurrency, attempts, context/output safety, and cleanup; token counts are telemetry. Metered Codex workers use aggregate token reservations, but Codex reports final usage only after a turn, so the runner cannot interrupt at an exact token count.
