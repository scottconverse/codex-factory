01 / Why it exists

Model names are not capability evidence

Stop guessing which worker should get the job.

A model can summarize correctly and still fail to return a safe file patch. A candidate can pass today and become stale after a runtime or harness change. A cheap worker is not cheap if it spins without producing a usable artifact.

Codex Factory turns those differences into an operator-visible roster. Qualification is tied to the exact candidate and role, selection prefers qualified free local capacity, and paid routes remain explicitly budget-gated.

02 / The operating loop

A small control plane around existing runtimes

Discover. Qualify. Route. Supervise. Retain.

  1. 01

    Discover the floor

    Inventory every installed Ollama model and the Codex candidates declared by the operator. Embedding-only models remain visible but are not invoked as workers.

  2. 02

    Qualify exact roles

    Run analysis, reasoning benchmark, structured-write, or workspace-write harnesses. The latest result for the exact fingerprint wins.

  3. 03

    Select by policy

    Require the right role and tier, then prefer a qualified free local candidate before metered Codex capacity.

  4. 04

    Run one bounded shift

    Preview first. Admission locks the factory, reserves paid usage when applicable, starts one owned process, and never retries automatically.

  5. 05

    Keep the receipt

    Retain the request, events, diagnostics, final message, terminal result, and usage record for coordinator acceptance.

03 / Controls

Bounded by design

The worker does the shift. The coordinator keeps authority.

Version 0.1.2 concentrates on admission, execution, and evidence—the narrow layer already implemented and testable.

QUALIFICATION

Role failures stay local

A failed structured-write check does not remove a model that still qualifies for read-only analysis.

ADMISSION

Paid use is explicit

Codex candidates require an opt-in qualification flag and a remaining aggregate reservation.

PROCESS

Timeouts own the process tree

The supervisor handles timeout and interrupt cleanup; an unreaped process preserves the lock as a stop condition.

EVIDENCE

Completion is not acceptance

A clean CLI exit is recorded as process completion. It does not claim the requested work is correct.

05 / Receipts

Evidence survives the shift

Enough context to accept, reject, or investigate.

Each run retains the exact request, JSONL events, stderr diagnostics, final message, terminal result, and aggregate usage record. Raw receipts remain local and ignored by Git because they can contain repository data.

06 / First shift

Node.js 24+ · Git · Codex CLI

Inventory first. Spend nothing.

The qualification command previews every applicable candidate and harness pair by default. Add --execute to test free local candidates. Paid Codex models remain excluded unless you add --include-paid.

Open the user manual
PowerShell
> git clone https://github.com/scottconverse/codex-factory.git
> cd codex-factory
> npm.cmd run check

# Preview candidate × harness plan
> npm.cmd run fleet:qualify

# Execute free local qualification
> npm.cmd run fleet:qualify -- --execute

# Preview one automatically selected route
> node scripts/run-worker.mjs `
    --task-id inspect-repo `
    --role local-read `
    --cwd . `
    --prompt-file examples/inventory.prompt.md
07 / Honest boundary

Evidence-producing prototype

A useful supervisor. Not yet the whole factory.

Version 0.1.2 proves discovered, qualification-gated selection and bounded single-worker execution. It is suitable for controlled experiments on a host you operate—not unattended product delivery.

WORKING NOW
  • Dynamic Ollama inventory plus configured Luna, Terra, and Sol candidates
  • Exact, role-scoped qualification fingerprints
  • Free-local-first selection from the qualified pool
  • Constrained local structured-file patch path
  • One owned worker process with timeout and receipts
NOT IN 0.1.2
  • Parallel scheduler or campaign dependency graph
  • PM-facing control room or remote web application
  • Automatic semantic acceptance, merge, or release
  • MCP server or autonomous repository-wide local agents
  • Hard token cutoff during a Codex turn
Two kinds of budget

Local Ollama workers use wall time, concurrency, attempts, context/output safety, and cleanup; token counts are telemetry. Metered Codex workers use aggregate token reservations, but Codex reports final usage only after a turn, so the runner cannot interrupt at an exact token count.
